# ai-consultant

[English](README.md) · Русский

ИИ-консультант, который отвечает клиентам компании по прайсу и частым вопросам. Один движок,
два входа: виджет, который ставится на сайт одной строкой, и Telegram-бот. Под каждым ответом
виден фрагмент, из которого он взят. Если в базе ответа нет, консультант так и говорит, ничего
не выдумывает и предлагает менеджера. Менеджер получает заявку в Telegram вместе со всей
перепиской.

Демо-база — вымышленная пекарня «Колосок»: прайс, доставка и оплата, частые вопросы.

## Быстрый старт

```bash
docker compose up --build
```

http://localhost:8000/ — сайт вымышленной пекарни с виджетом на сервере,
http://localhost:8000/browser.html — режим, где поиск идёт на устройстве посетителя. Настраивать ничего не нужно: без ключа модели ответом служит
найденный фрагмент.

Боту нужен `TELEGRAM_BOT_TOKEN` в `.env` (см. `.env.example`): `docker compose --profile bot up`.

На сайт:

```html
<script src="https://consultant.example.com/widget.js" defer></script>
```

Цвета и шрифт виджет берёт у сайта из CSS-переменных на странице (`--consultant-accent`,
`--consultant-accent-text`, `--consultant-font`). Переписка не пропадает, когда посетитель переходит
на другую страницу сайта, пока вкладка открыта. Кнопки на странице могут открыть чат или задать
вопрос: `AiConsultant.open()`, `AiConsultant.ask("...")`.

### Демо-сайт

В `widget/` лежит сайт вымышленной пекарни «Колосок»: главная, о пекарне, меню, доставка и адрес.
Он собран на шаблоне [Business Casual](https://github.com/StartBootstrap/startbootstrap-business-casual)
от Start Bootstrap (MIT) с Bootstrap 5.2.3, шрифты Lora и Raleway (OFL) отдаются с самого сайта, фото —
с Wikimedia Commons под CC0 и CC BY 2.0 (авторы на `credits.html`). Цены, часы и правила на страницах
взяты из `knowledge/kolosok/`, так что сайт и консультант не расходятся.

## Как отвечает

1. **База.** Markdown-файлы в `knowledge/<компания>/`. Каждый раздел `## ` становится фрагментом,
   спереди заголовки («Доставка и оплата › Самовывоз»). Загруженный `.txt`, `.md` или `.pdf` (до
   300 КБ и 20 страниц) режется так же и живёт только до конца сессии.
2. **Поиск.** Гибридный. Локальная модель `multilingual-e5-small` (int8 ONNX, 118 МБ, около 10 мс
   на вопрос на процессоре, без API) находит 12 кандидатов в PostgreSQL с pgvector. Затем для
   каждого считается взвешенная доля слов вопроса, которые в нём есть: редкие слова весят
   больше. Обе оценки складываются.
3. **Ответ или «не знаю».** Лучший фрагмент должен пройти оба порога: смысл ≥ 0.79 и слова ≥ 0.40.
   Без модели ответом служит сам фрагмент, а если второй почти не хуже, то и он («сколько стоит
   доставка» показывает цену по городу и за город). С моделью (GigaChat или любой
   OpenAI-совместимый API) порог по словам снижается до 0.20. Модель пишет ответ по трём лучшим
   фрагментам, а если ответа в них нет, отвечает `НЕ_ЗНАЮ`.
4. **Менеджер.** «Позвать менеджера» или фраза вроде «перезвоните мне» запускает короткую
   анкету: имя, телефон (проверяется и приводится к +7…), что передать. Заявка сначала
   сохраняется, потом уходит в `MANAGER_CHAT_ID`, поэтому сбой Telegram её не теряет.

Переключатель «Как ищется ответ» показывает всех кандидатов с обеими оценками. Клиент видит,
почему консультант ответил или отказался.

### Почему гибридный

Одна оценка e5 не отделяет вопросы, которых нет в базе. На демо-базе самый слабый вопрос из базы
(«Почём медовик?») получил 0.802, а «Сколько стоит ремонт iPhone 15?» — 0.812. Слова их разделяют:
с базой вопрос про iPhone делит только «стоит», а «стоит» есть во многих фрагментах прайса,
поэтому весит мало. Пороги подобраны на 21 вопросе: из `knowledge/kolosok/smoke.json` и из прогона
при разработке.

Честная цена такого подхода — несколько отказов там, где ответ в базе есть, но другими словами.
У вопроса «Привезёте торт завтра?» слишком мало общих слов с фрагментами о доставке, и
консультант предлагает менеджера. С включённой моделью порог по словам ниже, и такие вопросы
проходят.

## Режим в браузере

`data-mode="browser"` запускает тот же поиск на устройстве посетителя: transformers.js и тот же
ONNX-файл. Демо ничего не стоит, и данные не покидают устройство. `scripts/export_index.py`
пишет `kb-index.json` с фрагментами, их векторами, порогами и стоп-словами, а
`widget/kb-search.js` шаг за шагом повторяет `app/lexical.py` и `app/search.py`. На 21 проверочном
вопросе оба режима приходят к одному решению, ответить или отказаться. Векторы расходятся в
третьем знаке: в браузере другая сборка onnxruntime. Модели, чтения PDF и отправки заявок в этом
режиме нет. Вместо отправки виджет показывает сообщение, которое получил бы менеджер.

### Статическая сборка

`python scripts/build_static.py dist/` собирает папку для любого веб-сервера: страница пекарни с
открытым виджетом, индекс и `Build/` с transformers.js, WebAssembly onnxruntime-web и моделью. Рядом
с каждым файлом лежит готовый `.gz` для `gzip_static` в nginx: 163 МБ на диске, около 92 МБ по сети.
С CDN ничего не грузится. Странице нужна CSP с `'wasm-unsafe-eval'` и `worker-src 'self' blob:`.

## Лимиты

| Настройка | По умолчанию | Что происходит |
|---|---|---|
| `MESSAGES_PER_DAY` | 10 | вопросов с посетителя в сутки (IP или Telegram id, хеш с солью); дальше вежливая остановка с кнопкой менеджера, анкета остаётся доступной |
| `DAILY_TOKEN_BUDGET` | 200 000 | модель выключается до конца дня, ответы идут из фрагментов |
| `LLM_CONCURRENCY` | 1 | вызовы модели идут через очередь, у GigaChat для физлиц один поток |
| `QUEUE_MAX` | 20 | если ждущих больше, посетителя просят повторить через минуту |

## Публичное демо

`DEMO_LEADS=1` — для демо, открытого всем: анкета менеджера проходит до конца, но заявка не
сохраняется и никуда не уходит, посетитель видит сообщение, которое получил бы менеджер. Имена и
телефоны случайных людей нигде не остаются. С пустым `DATABASE_URL` база, сессии и загрузки живут
в памяти, так что демо — один контейнер без PostgreSQL. Ему нужно около 480 МБ памяти: токенизатор
многоязычной модели занимает около 285 МБ, сама модель около 130 МБ. Так работает демо на
[dognellaf.com](https://dognellaf.com/case/ai-consultant/).

```bash
docker build -t ai-consultant .
docker run -d -p 8000:8000 -e DEMO_LEADS=1 -e QUOTA_SALT=$(openssl rand -hex 16) ai-consultant
```

## Модели

`LLM_PROVIDER=none` (по умолчанию), `gigachat` или `openai`. Провайдер скрыт за одним вызовом
`complete()` (`app/llm.py`), смена провайдера — это правка `.env`.

Про условия GigaChat. Бесплатный режим для физлиц (365 млн токенов в год) разрешён только для
личного некоммерческого использования. Консультанту на сайте клиента нужен платный пакет (для
физлиц от 1 300 ₽ в месяц за 20 млн токенов GigaChat 2 Lite) или договор самого клиента со
Сбером. GigaChat работает с сертификатами Russian Trusted Root CA: скачайте их на Госуслугах и
укажите путь в `GIGACHAT_CA_BUNDLE`.

## Данные

Демо-база вымышленная. Заявки (имя, телефон, переписка) хранятся в PostgreSQL на сервере
клиента, в учёте лимитов только хеш посетителя с солью. Загруженный файл живёт в памяти и в
коллекции сессии и удаляется вместе с ней (через час). С GigaChat вопросы и фрагменты остаются в
России, в режиме браузера — на устройстве посетителя.

## Разработка

```bash
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt -r requirements-dev.txt
python scripts/download_model.py
pytest                                   # 59 тестов, смоук идёт на настоящей модели
TEST_DATABASE_URL=postgresql://... pytest tests/test_pgstore.py
ruff check . && ruff format --check .
uvicorn app.api:app --reload             # без DATABASE_URL всё хранится в памяти
```

`tests/test_smoke.py` — приёмочная проверка: 10 вопросов из FAQ находят свой фрагмент, 3 вопроса
не по теме получают «не знаю».
